Commencez en 2 Minutes

  1. Connectez votre compte GitHub
  2. Sélectionnez votre dépôt

Aucune connaissance en Kubernetes, Docker ou GitLab CI requise !

Gestion de Code : Github

1. Créer un nouveau dépôt GitHub

Étape 1 : Accéder à GitHub

Connectez-vous à GitHub et cliquez sur "+" puis "New repository"

Étape 2 : Configurer le dépôt

  • Nom du dépôt : Choisissez un nom descriptif (ex: "mon-projet-angular")
  • Description : Optionnelle mais recommandée
  • Visibilité : Public (gratuit) ou Privé (nécessite un compte pro)
  • Cochez "Add a README file"

Étape 3 : Valider la création

Cliquez sur "Create repository". Votre URL sera de la forme :

https://github.com/[votre-username]/[nom-du-dépôt].git

2. Utiliser ce dépôt dans notre plateforme

Étape 1 : Autoriser l'accès

Notre plateforme demandera l'autorisation d'accéder à votre dépôt GitHub. Cliquez sur "Authorize".

🔒 Nous utilisons les API officielles de GitHub et ne stockons jamais vos identifiants.

Étape 1 : Coller l'URL GitHub

Dans notre plateforme, après vous être authentifié via votre compte GitHub, sélectionnez l'opération Git que vous souhaitez exécuter en cliquant sur "operation Git" et collez l'URL de votre dépôt :

🔍 Problèmes fréquents

Je ne vois pas mon dépôt après connexion

Vérifiez que vous avez bien autorisé l'accès à l'organisation GitHub contenant le dépôt.

Erreur d'autorisation

Révoquez les droits de notre application dans vos paramètres GitHub puis réessayez.

Pipelines CI : GitLab

1. Importer un dépôt existant vers GitLab

Étape 1 : Créer un nouveau projet

Connectez-vous à GitLab et cliquez sur "New project"

Étape 2 : Sélectionner l'import

Choisissez l'onglet "Import project" puis sélectionnez "GitHub"

Étape 3 : Connecter GitHub

  1. Autorisez l'accès lorsque demandé
  2. Sélectionnez votre dépôt GitHub

🔒 La connexion utilise l'API officielle GitHub OAuth

2. Suivi de l'importation

L'import peut prendre plusieurs minutes selon la taille du dépôt. Vous verrez :

Actualisez la page pour voir la progression

Étape 3 : Obtenir l'URL GitLab

Après l'import, copiez l'URL de votre nouveau dépôt GitLab :

  1. Cliquez sur "Clone" dans votre projet GitLab
  2. Copiez l'URL HTTPS (format ci-dessous)
https://gitlab.com/votre-utilisateur/votre-projet.git

Étape 4 : Coller l'URL GitLab

Dans notre plateforme, après avoir collé votre URL GitLab, puis sélectionnez Le langage de votre projet ,L'image Docker appropriée et Les jobs CI. Cliquez sur "Générer le fichier" Le fichier .gitlab-ci.yml est alors automatiquement créé en fonction de vos sélections

Le fichier généré peut être modifié en cliquant sur "Modifier", puis enregistré pour appliquer les changements.

Étape finale : Déploiement sur GitLab

1. Cliquez sur "Déployer sur GitLab"

Après validation de votre configuration CI/CD, lancez le processus complet en cliquant sur le bouton "Deployer sur Gitlab"

⚠️ Vérification de compte obligatoire

Si votre compte GitLab n'est pas complètement vérifié :

  • Une fenêtre modale s'affiche avec un lien de vérification
  • Vous devrez confirmer votre numéro de téléphone
  • Cette étape est essentielle car :
    1. GitLab l'exige pour tous les déploiements CI/CD
    2. Elle sécurise l'exécution des pipelines
    3. Elle prévient les abus du système
    4. Elle active les fonctionnalités complètes de GitLab

2. Finalisation du processus

Complétez la vérification sur GitLab par cliquez sur "j'ai Terminé la verification" dans la modale et puis relancez le déploiement en cliquant à nouveau sur "Deployer sur Gitlab"

Notre plateforme commit et push automatiquement le fichier .gitlab-ci.yml dans votre dépôt GitLab, déclenche immédiatement l'exécution du pipeline, puis vous redirige vers l'interface pour suivre son avancement.

🔍 Problèmes fréquents

Échec de l'authentification GitHub

Solution : Révoquez les permissions dans GitHub Settings > Applications puis réessayez.

Dépôt vide après import

Solution : Vérifiez que le dépôt source n'est pas vide et que vous avez les permissions nécessaires.

🔍 Problèmes fréquents

Échec de la détection automatique

Cause : Fichiers caractéristiques manquants ou structure de projet non standard

Solution :

  • Vérifiez que votre dépôt contient bien :
    • package.json pour Node.js
    • pom.xml ou build.gradle pour Java
    • requirements.txt pour Python
  • Si vous utilisez une structure non standard, spécifiez manuellement le langage
Port déjà utilisé

Cause : Le port spécifié est occupé par un autre service

Solution :

  • Changez le port de votre application dans son fichier de configuration
  • Ou spécifiez un port hôte différent dans les paramètres Docker : 
    ports:
  - "NouveauPort:PortConteneur"
  • Listez les ports utilisés avec : netstat -tuln (Linux) ou Get-NetTCPConnection (PowerShell)
Problèmes de version incompatibles

Cause : La version du langage utilisée ne correspond pas aux exigences du projet.

Solution :
  1. Identifiez la version requise :
    • Consultez le fichier de configuration du projet :
      • package.json (Node.js)
      • pom.xml ou build.gradle (Java)
      • requirements.txt (Python)
    • Recherchez les indications de version (ex: "node": ">=16.0.0", java.version=17)
  2. Mettez à jour votre environnement :
    • Installez la version correspondante localement
    • Configurez votre outil de déploiement pour utiliser cette version
  3. Bonnes pratiques :
    • Privilégiez les versions LTS (Long Term Support)
    • Documentez clairement les exigences de version
    • Testez systématiquement les mises à jour

ℹ️ La plupart des projets documentent leurs exigences de version dans leur fichier de configuration principal.

Échec d'installation des dépendances

Cause : Problème avec npm/pip/Maven/Gradle

Solution :

  • Node.js :
    • Supprimez node_modules et package-lock.json
    • Relancez npm install
  • Python :
    • Créez un environnement virtuel : python -m venv venv
    • Activez-le puis : pip install -r requirements.txt
  • Java :
    • Maven : mvn dependency:purge-local-repository
    • Gradle : Supprimez le dossier .gradle
